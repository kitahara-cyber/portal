# 定例資料の自動作成（毎営業日の手順）

この手順は、スケジュール実行のたびに新しいセッションで読んで、そのとおりに進める。
目的：**翌営業日の顧客定例の資料を前日のうちに作り、顧客ポータルの「定例資料」タブに入れ、担当ディレクターに Slack で知らせる。**

## 0. 準備
- リポジトリ `kitahara-cyber/portal` を作業場所にする（このファイルは `_build/teirei/RUNBOOK.md`）。
- `pip install cryptography --break-system-packages`（入っていなければ）
- 設定シート（社外秘・北原さんのみ閲覧）：`12KOCRonS_yRM-y-PrH12S50_tHzXDQC-zMwwXk1s-DU`
  - 「顧客」タブ：SIS／会社名／照合キーワード／状態／担当／共有シートID／ポータルの場所／パスワード／保存キー
  - 「担当」タブ：担当／カレンダー（メール）／SlackユーザーID、11〜12行目に「顔写真の鍵」
  - 「実行ログ」タブ：1件ごとに1行追記する
- 日次報告：スプレッドシート `19BxCNocKdGOyoDrrDiji3AeiRiWkPmMbCwthV6NcPeg` の「集計」タブ（D列 SIS 〜 S列 アポ獲得件数）
- コマンドはすべてリポジトリの一番上で実行する。作業用フォルダは `work/`（.gitignore 済み。最後に消す）

## 1. 対象の定例を見つける
1. 今日（日本時間）が土日祝なら何もしないで終わる。
2. 対象日＝翌営業日。金曜なら土・日・月の3日分を対象にする。
3. 「担当」タブの全員のカレンダー（＋ kitahara@writeup.co.jp）で、対象日の予定を list_events で取る。
4. 予定名に「定例」「定例MTG」「定例会」「週次MTG」「報告会」「報告回」「お打ち合わせ」「MTG」などがあり（「報告会」は林さんの定例の呼び方。11/6〜定例として扱う）（「お打ち合わせ」「MTG」だけのものは顧客タブで状態が稼働中の会社に限る）、「顧客」タブの照合キーワード（または会社名の一部・読みの違い。例：「みんなのミカタ」→ミンナのミカタHD）に当たるものを拾う。社内会議（CSMTG・朝礼など）や、顧客タブにない会社は対象外。迷うものは対象外にしてログに理由を書く。
   - **お客様が出る会議だけ**を対象にする。次のどれかに当てはまるもの：予定名に「様」か「【定例】」がある／参加者に writeup.co.jp と synapse.work0@gmail.com 以外のアドレスがいる／説明文に「ゲスト会社名」がある。社内の人だけで、予定名に「様」もない会議（例：「みんなのミカタ定例MTG」を社内で開くもの）は対象外。
5. 同じ会社・同じ日時が複数のカレンダーに出ても1件にする。「実行ログ」に同じ SIS・同じ定例日時で「作成済み」があればスキップ。
6. 前回の定例日：その会社の照合キーワード（または会社名の一部）で過去60日の担当カレンダーを fullText 検索し、上の「お客様が出る会議」の条件に合う予定のうち一番新しい日付（なければ空）。予定名が毎回同じとは限らない。

## 2. データを取る（1社ごと）
- 日次報告：`集計!D1:S10000` を get_values（大きいのでファイルに保存される）→ `work/crm.json` にコピー（1回の実行で1回でよい）。
- 共有シート（顧客タブの共有シートID。空なら日次報告だけで作る）
  1. get_spreadsheet でタブ名と行数を見る。「案件概要・運用ガイド」などに今使っているリストの指定があればそのタブ、なければ架電履歴の列があるタブ（「営業リスト」「◯月分」「◯◯営業リスト」など）を全部使う（期間外の記録は calc.py が自動で外す）。
  2. 各タブの見出し `タブ!A1:BZ3` を取り（見出しが2行のタブもある）、`python3 _build/teirei/cols.py <見出しの保存ファイル> <タブ名> <行数>` で取る範囲を出す。
  3. 出た範囲を **1つずつ順番に** get_values し、保存ファイルを `work/<SIS>/<タブ>_<n>.json` にコピー（並べて呼ぶと取り違えるので、必ず1件ずつ。結果の range がタブ名と一致しているか確かめる）。
     - 行数が1万行を超えるタブは、9000行ずつに分けて取り、python で values をつないで1ファイルにする（見出し行は最初の1回だけ）。
     - 結果が小さくてファイルに保存されず画面に出たときは、その JSON をそのまま `work/<SIS>/…json` に書く。
- spec を書く（`work/<SIS>/spec.json`）：
  `{"sis":"5473","name":"会社名","meeting":"YYYY-MM-DD","prev":"前回定例日 or 空","crm":"work/crm.json","tabs":[{"name":"営業リスト","files":["…_1.json","…_2.json"]}]}`
  （1つのタブを複数範囲に分けて取ったときは、その順に files に並べる）
- `python3 _build/teirei/calc.py work/<SIS>/spec.json > work/<SIS>/data.json`

## 3. 文章を書く（story.json）
data.json を読み、必要なら次も見てから、お客様向けの文章を書く。
- 前回の定例の議事録（Drive で `title contains '<キーワード>'` の Gemini メモ、または「◯◯様 ✖️ライトアップ_アウトバウンドコール支援」）
- 共有シートの「スクリプト」タブ（冒頭トークの見直しに使う）、「管理表_商談アポ」（アポのその後）

`work/<SIS>/story.json` の形（どれも省略可。省略した項目は数字から自動で文章になる）：
```json
{"summary":"結論の1文。大事な語だけ <em class=\"hl\">…</em>",
 "trend":"…","result":"…","ng":"…","list":"…",
 "issues":[{"t":"題名","body":"中身（数字つき）"}],
 "proposals":[{"t":"題名","why":"理由","kpi":"次回の定例で確かめる目標"}],
 "plan":["ライトアップが進めること"],"asks":["お客様にお願いしたいこと"],
 "navi":{"summary":"担当ナビの吹き出し（章ごと。数字の受け止め方を先回りして話す）"}}
```
data.json の `checks` に注意書きがあれば必ず読む。
- 「アポ数が日次報告と共有シートで違う」とき：共有シートの数を正とし、story.json に `"override":{"apo":<シートのアポ数>,"lead":<シートの資料送付数>,"note":"アポ・資料送付の件数は、共有シートの架電記録（前回の定例以降）から数えています。"}` を入れる。Slack の「確認してほしいこと」にも両方の数字を書く。
- 「記録が架電数より大幅に多い」とき：spec の prev やタブの選び方を見直す。直らなければ Slack に書く。

書き方の決まり：
- お客様に向けた言葉で書く。社内向けの言い方（「決して悪くない」「頑張ります」等）や社内の事情は書かない。
- 数字は data.json にあるものだけ。推定は書かない。
- 他のお客様の社名は出さない（業種だけ）。
- ご提案は3つまで。それぞれに「なぜ」と「目標」を付ける。目標の数値（例：30%→20%）は提案として置いてよいが、Slack の「確認してほしいこと」で担当に決めてもらうよう書く。

## 4. 資料を作ってポータルに入れる
1. 顔写真：`python3 _build/teirei/avatar.py <顔写真の鍵> <担当名> work/<SIS>/avatar.txt`
2. `python3 _build/teirei/deck.py work/<SIS>/data.json work/<SIS>/story.json work/<SIS>/deck.html --director <担当名> --avatar work/<SIS>/avatar.txt --kn _build/daily/knowledge.enc --key <鍵> --sis <SIS>`（ご提案の章に「魔法の一言」、お願い事項に「商材について教えてください」が入る）
3. ポータルに入れる：
   - ふつうの会社（ポータルの場所が `c/<SIS>/`）：
     `python3 _build/teirei/embed.py c/<SIS>/index.html <パスワード> work/<SIS>/deck.html <定例日 YYYY-MM-DD>`
   - アクロネット（`acronet/`）・アイクリック（`aiclick/`）は専用ポータルなので埋め込まない。代わりに別ページで公開する（先に `mkdir -p <場所>teirei/<YYYYMMDD>`）：
     `python3 _build/teirei/lock.py work/<SIS>/deck.html <場所>teirei/<YYYYMMDD>/index.html --password <パスワード> --title "<会社名> 様 定例資料" --eyebrow "MEETING DECK" --standalone --storage-key <保存キー>`
4. 確認：`python3 -c` などで、embed 後のファイルにお客様名の平文が増えていない（暗号化されている）こと、`teirei-data` が平文で残っていないことを確かめる。
5. `git add -A && git commit -m "定例資料：<会社名> <定例日>" && git pull --rebase && git push`
   コミットの最後に次の2行を付ける：
   `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## 7. 継続提案資料（契約満了の前月・満了月の定例）
定例資料とは別に、**契約満了の前月と満了月の定例**には継続提案資料を作り、担当ディレクターに知らせる（例：12月満了なら、11月の定例と12月の定例）。
料金・割引・特典は AI が決めない。担当が埋める「下書き」として渡す。

### 7-1. 対象を見つける（毎営業日）
1. 「顧客」タブで、契約中・請求停止（と「稼働中として扱う」の例外）の会社ごとに満了日を決める：L列「契約満了月（更新情報）」。空なら JD シート「パートナー一覧」の「1年目の契約満了月」。
   満了日が今日より前なら、1年ずつ足して、今月以降になるまで進める（自動更新の扱い）。
2. 満了月が「今月・来月」の会社だけを対象に、1章で見つけた**翌営業日（金曜は土〜月）**の定例のうち、その会社のものを拾う（定例資料と同じく、前日の朝に作って送る）。
3. 定例の月が「満了月の前月」なら段階＝`2か月前`、「満了月」なら段階＝`満了月`。それ以外は対象外。
4. 「実行ログ」に同じ SIS・同じ段階で「継続提案 作成済み」があればスキップ（1つの段階につき1回）。

### 7-2. データを取る
- 2章と同じ手順で日次報告と共有シートを取る。spec の `prev` は**今期の始まり**（満了日の1年前の翌日。契約開始月がそれより後なら契約開始月の1日）にする。
- `python3 _build/teirei/calc.py work/<SIS>/spec.json > work/<SIS>/data.json`
- `work/<SIS>/facts.json` を書く：
  `{"start":"<契約開始月 YYYY-MM-01>","end":"<満了日 YYYY-MM-DD>","fee":<月額>,"init":<初期費用>,"status":"<契約状況>","measures":"<施策>","appts":<work/jd.json の appts（jd.py の出力。なければ空）>,"price":<単価>,"meeting":"<定例日>","stage":"<段階>"}`
  - 自動で埋めるための材料（あれば入れる。無い欄は資料が自動で文章を作る）：
    `"themes":[["関心のテーマ",件数]]`（JD「商談管理表一覧v2」のその会社のヒアリング内容（P列）から、事例・費用・人手不足などのテーマを数える）、
    `"hooks":["ヒアリング内容の要約（新しい順に4つ）"]`、`"magic":[{"line":"…","why":"…"}]`（knowledge.enc の魔法の一言）、
    `"list_cond":{"ind1":[…],"size":[…]}`（knowledge.enc のリスト提案。無ければ省略）、
    `"appts"` が JD に無い会社は、共有シートの「管理表_商談アポ」系タブ（今期のアポ取得日の行）から `{"total":行数,"done":実施の有無=実施,"res":{進捗ステータスの件数},"blank_past":商談日が過ぎて実施が空}` を作り、`"appts_label":"今期"` を付ける。
    `"improve":[{"d":"YYYY-MM-DD","what":"変えたもの","detail":"変えた内容","before":"…","after":"…"}]`（記録シート `1sA96H5h0UoUAW7kHrqaCuPu9_s6THgP9b50olIOnMQI` の「現場の改善」タブで、その SIS の今期の行）、
    `"rules":{…}`（下の「継続の条件」）、
    `"plan_input":{"name":…,"price":…,"discount":…,"term":…,"renew":…,"unit_price":…}`（記録シートの「継続条件」タブで、その SIS の一番下の行。D〜I列。無ければ省略）
  - 単価：Drive の「運用中のお客様一覧（商材・単価・ターゲット）」（`1vqMuaqy6mT_8xVhrpZqK-asz-NokU7CtxmiSZQ37Jhs`）で③の確かさが「確認済み」のときだけ、③の金額（範囲なら下限）を円で入れる。それ以外は 0。

### 継続の条件（会社のルール。決まったらここに書く）
- rules = `{}`（未設定）。会社共通の継続割引・契約期間・更新条件が決まったら、ここに書く。
- 料金・割引・期間・条件・単価は、AI が決めた値を資料に入れない。担当が記録シートの「継続条件」タブに書いたものだけが資料に入る。書かれていない欄は資料に出さず（8章は「担当よりご案内します」）、Slack で担当に AI の案を送る。

### 7-3. 文章を書く（renew_story.json）
読むもの：今期の議事録（Drive の Gemini メモ）、共有シートの「管理表_商談アポ」（相手の関心・商談の結果・失注の理由）・「スクリプト」タブ、商材ノート（Drive「商材情報（インサイトセールス・社外秘）」）、`_build/daily/knowledge.enc` の魔法の一言。
```json
{"summary":"今期の結論1文（<em class=\"hl\">…</em>可）","review_note":"実施内容の補足",
 "voices":{"interest":["関心を持たれた点（hooksから。件数があれば添える）"],"ng":["断り理由（シートで数えられない場合だけ）"]},
 "talks":[{"line":"刺さった一言","why":"根拠"}],"field":["アポの質・商談の手応え（議事録から）"],
 "gaps":[{"t":"届かなかった点","why":"要因"}],"done":[{"t":"実施した改善","effect":"効果（数字）"}],"history":[{"d":"2026-03","t":"リスト・トークの見直し"}],
 "target_note":"目標の補足","market_note":"市場の余地の補足",
 "proposals":{"target":["…"],"talk":["…"],"combo":["…"],"team":["…"]},
 "ops":{"meeting":"…","report":"…","team":"…"},
 "plan":{},"next_months":12,"navi":{"review":"…"}}
```
- 2章の書き方の決まりに従う（数字は data.json・facts.json と読んだ記録にあるものだけ。他のお客様の社名は出さない）。
- 分からない欄は書かない（資料では【担当が記入】と出る）。**plan（料金・割引・特典・契約期間・更新条件）は空のままにする。**
- 段階が `満了月` のときは、前月に作った資料からの変化（その後1か月の数字）を summary に入れる。

### 7-4. 資料を作って、担当にだけ見える場所に置く
1. `python3 _build/teirei/renew.py work/<SIS>/data.json work/<SIS>/facts.json work/<SIS>/renew_story.json work/<SIS>/renew.html --director <担当名> --avatar work/<SIS>/avatar.txt --sis <SIS>`
   （出力の `todo` が【担当が記入】の数）
2. `mkdir -p renew/<SIS>/<定例日YYYYMMDD>` して、**社内ポータルのパスワード**（担当タブ）で鍵をかける（お客様のパスワードは使わない）：
   `python3 _build/teirei/lock.py work/<SIS>/renew.html renew/<SIS>/<YYYYMMDD>/index.html --password <社内ポータルのパスワード> --title "<会社名> 様 継続のご提案（下書き）" --eyebrow "INTERNAL ／ 社外秘" --standalone --gzip --storage-key cs-pw`
3. 平文に会社名・数字が残っていないことを確かめて、commit・push（4章 5. と同じ）。
